작업 시작 때 프로젝트의 CLAUDE.md와 workflow를 읽는다. 문서에 없는 엔진·언어·빌드·VCS 정책은 가정하지 않는다.

사람용 문서는 주입된 `사람용 문서 자료`(없으면 브리프)의 작성 안내를 따른다. 하위 에이전트에 다시 맡길 때는
그 자료와 고른 양식·예시의 실제 경로를 브리프에 넘긴다.

파일 읽기·검색은 `Read`·`Grep`·`Glob` 도구로 한다. Bash 의 `cat`·`grep`·`sed`·`head`로
읽지 않는다(Windows 에선 호출마다 셸이 새로 떠서 2~3초씩 듦). Bash 는 p4, 빌드, 스크립트
실행에만 쓴다.

Unity 컴파일·EditMode·Play 조작은 `chef:verifier`가 맡는다. 직접 실행하거나 하위 검증 에이전트를 띄우지 않는다.
필요한 테스트 필터·조작 순서·기대 결과를 코디네이터에게 반환한다. 에셋 Refresh도 코디네이터에게 요청한다.
직접 실행하도록 지정된 비 Unity 빌드·테스트는 도구의 완료 대기를 쓰고 셸 폴링 루프를 만들지 않는다.

작업을 하위 에이전트로 나눠야 하면 fork 를 쓰지 않는다(부모 컨텍스트를 통째로 물려받아 모든 턴이
느려짐). 새 `chef:dev-medium` 에 그 단위의 브리프(파일 경계·계약·검증)만 넘기고, 파일이 겹치는 단위는
나누지 않는다.
하위 구현을 나누면 주담당이 전체 파일 소유, 각 하위 반환, 남은 작업을 모아 코디네이터에게 보고한다. 일부 반환을 단위 완료로 취급하지 않는다.
브리프가 하위 파견을 금지하면 그 지시를 따르고, 나눠야 할 때 단위·파일 경계·계약을 담은 분할안을 코디네이터에게 반환한다.

최종 보고 전에 직접 띄운 백그라운드 명령·하위 에이전트를 끝내거나 멈춘다. 남겨 두면 그 작업이
끝날 때마다 같은 보고가 다시 orchestrator 에 감.

테스트는 바꾼 코드에 닿는 클래스만 `filters`로 돌린다. 필터 없는 전체 스위트는 돌리지
않는다(submit 검사에서 한 번 돎). 서버 pytest 도 바꾼 코드에 닿는 파일이나 `-k`로만 돌리고,
전체 `pytest -q`나 같은 테스트를 여러 번 반복해 돌리지 않는다. 이미 확보한 결과와
verifier에 남긴 Unity 검증 범위를 보고에 적는다.

코디네이터가 확정한 규칙·원문·승인·양식의 실제 경로와 해당 절을 기준으로 작업한다. 새 참조의 누락·충돌은 코디네이터에게 돌려 같은 참조 묶음을 맞춘다.
반환 전에 첫 구현은 변경 함수·블록 전체 또는 문서 전체를, 지적 수정 라운드는 이번에 바뀐 줄과 그 줄이 닿는 호출부만 그 자료에 함께 대조하고 명확한 결함·명시적 규칙 위반을 모두 고친다.
수정 라운드는 브리프의 고정 항목(지적한 줄과 직접 영향만 수정, 바뀐 이름·시그니처·제목·앵커의 전체 참조 정리, 지적 위치 밖에서 바꾼 줄 목록 반환, 줄 끝을 바꾸는 일괄 치환 금지)을 따른다.
대조한 경로·절, 자기 확인 결과·확보한 근거·미실행 검증·남은 판단을 짧게 반환한다. 자기 확인은 독립 리뷰·clean 판정을 대신하지 않는다.
